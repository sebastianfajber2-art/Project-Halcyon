# Hook library

What works in the "real Iron Man suit" niche, measured from YouTube data, and scripts written from it.

| File | What it is |
| --- | --- |
| [hooks.md](hooks.md) | The three outlier videos (hooks, structure, why they likely worked), six reusable hook templates, a watchlist, caveats |
| [hooks.json](hooks.json) | The same entries in machine-readable form, for choosing a template quickly |
| [scripts/script-a-long-reality-check.md](scripts/script-a-long-reality-check.md) | About 4.5 min, grade the suit system by system (format from H1) |
| [scripts/script-b-arc-reactor-explainer.md](scripts/script-b-arc-reactor-explainer.md) | About 2.5 min, how the arc reactor would work and why it can't (format from H2) |
| [scripts/script-c-one-problem-short.md](scripts/script-c-one-problem-short.md) | About 47 s Short, "the one problem isn't the reactor", talking to camera with a shot list and three film cutaways (format from H3) |

## Using it

1. Pick a template from `hooks.md` that fits the idea.
2. Fill it with a number you can prove from the design document or the simulation.
3. Check the first 3 seconds: does the opening line create a question the viewer must stay to answer?
4. Write the voiceover with `|` marks between captions, then build the video the way `docs/content/README.md` describes.

## Refreshing it

Rerun the research every few months: search the niche on YouTube, take each channel's last 50 uploads, and compare each video's views with that channel's median. The method is described at the top of `hooks.md`.

## Rules for the scripts

- Every number in a script needs a source in its "Facts to keep exact" table. If a claim has no source there, verify it before filming.
- Take the pattern, not the content: no one else's footage, wording or title.
- Don't claim a result you haven't got ("solved", "proved", "tested") until it's true.
